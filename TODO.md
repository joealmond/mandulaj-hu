## 8. Decisions still open

- [x] ~~**All-caps H1, or sentence case?**~~ **Resolved: keep the caps, as a
      treatment.** It already was one — `text-transform` in CSS, never in the
      source string — so the sidebar, breadcrumb, TOC, backlinks, `og:title`
      and RSS were already sentence case. One title, one display rule, nothing
      actually inconsistent. Two conditions applied: the breadcrumb no longer
      uses caps (it was competing with the H1), and titles over 60 characters
      drop a type step so all-caps never runs to five lines.
- [x] ~~**Explorer on mobile?**~~ **Resolved: patched, not removed.** Navigation
      is worth more than seven points. `aria-expanded` now lives on the real
      `<button class="explorer-toggle">` that already carried `aria-controls`,
      mirrored by a MutationObserver so the explorer's own script cannot put it
      back on the container. Mobile accessibility is **100**. Small enough to
      send upstream — see `quartz-custom/plugins/panel/src/index.tsx`.
- [x] ~~**Keep both graphs?**~~ **Resolved: desktop only.** At phone width the
      nodes are ~4px and nothing reaches a 44px touch target. - Worth knowing: `display: desktop-only` alone recovered **nothing** —
      it only hides. The graph still pulled and executed pixi.js (637ms) and
      d3 (95ms) from a CDN. The container is now removed from the DOM before
      the graph initialises, which took pixi from 637ms to 153ms and mobile
      TBT from 170ms to 100ms. - The remaining 153ms is pixi's module import, which happens whether or
      not a container exists. Eliminating it entirely means disabling the
      graph outright. - Backlinks stay on mobile — the real sideways navigation.
- [x] ~~**Folder allowlist or toggle only?**~~ **Resolved: toggle only.** Folder
      location was an invisible second rule that made moves and cross-device
      publishing harder to predict. ADR-017 records the remaining risk and the
      default-deny metadata, attachment, link, plan, and audit controls.
- [ ] **Graph view renders only the current node.** Verified 2026-08-26: the

      e.g. `hashing-algorithm` 1 out / 2 in), the config is normal
      (`depth: 1`), a canvas is created, and pixi.js and d3 both load 200. It
      still draws a single dot on every page. Not caused by our changes — the
      mobile removal script does not fire on desktop (`matchMedia` false, graph
